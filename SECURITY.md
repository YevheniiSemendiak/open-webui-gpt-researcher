# Security policy

Do not report suspected vulnerabilities in a public issue. Contact the repository maintainers
through the private security-reporting channel configured on the eventual GitHub repository.

Reports should include affected versions, reproduction details, impact, and any suggested
mitigation. Particularly sensitive areas are cross-user source access, artifact authorization,
runner credential scope, prompt-injection escape into tools, and privileged Open WebUI API use.

No security-support window is promised until the first tagged stable release.
